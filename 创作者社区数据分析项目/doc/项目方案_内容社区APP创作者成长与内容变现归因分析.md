# 内容社区 APP 创作者成长与内容变现归因分析

**项目定位：** 平台数据分析师项目，用数据同时支持创作者运营、内容分发产品与商业化决策。  
**分析对象：** 图文内容社区 APP 中的创作者及其公开笔记。  
**数据规模：** 20,000 行创作者基础信息表 + 100,000 行笔记内容行为表，共 120,000 行。  
**数据性质：** 本方案中的数量、样例和字段均为用于项目展示的模拟数据，不含真实用户信息或公司内部数据。

---

## 一、项目要回答的 4 个核心业务问题

| 编号 | 核心业务问题 | 数据视角 | 运营视角 | 产品视角 | 对应决策 |
|---|---|---|---|---|---|
| Q1 | **哪些新人创作者最容易在首篇内容后停止更新，哪些早期信号可以在流失前识别？** | 对比不同首月曝光、首周发布频次、内容质量、互动和变现经历下的 30 日留存与 28 日流失差异；识别高流失、高可干预人群 | 明确应优先触达的创作者、触达时点和激励内容 | 判断是否需要在首篇发布后增加任务引导、内容诊断或二次发布入口 | 新人分层、召回名单、首周任务、冷启动产品流程 |
| Q2 | **头部创作者是否垄断了流量，新人拿不到曝光是内容质量不足还是分发规则不利？** | 计算曝光和收入的集中度、同质量内容的流量差、算法版本前后的结构变化 | 识别需要重点运营或治理的头部与高潜人群 | 评估推荐规则对新老创作者、不同内容质量档位的公平性和效率影响 | 新人流量池、内容质量分、流量分配与保底曝光规则 |
| Q3 | **从内容消费到广告分成、带货佣金，变现链路的主要堵点在哪里？** | 拆解曝光→点击→商品点击→成交→结算漏斗，区分广告与佣金贡献，定位类目和内容形态差异 | 为不同层级创作者提供匹配的变现任务和培训 | 优化商品挂载、内容详情页和商机匹配产品能力 | 商业化激励、选品、广告分成和佣金策略 |
| Q4 | **在有限预算下，应扶持哪类创作者、采用什么扶持方式，才能同时改善留存、内容供给和变现规模？** | 基于分层优先级、增量效果、成本与收入弹性评估策略组合；用实验或准实验验证增量 | 分配培训、流量券、任务奖励和运营人力 | 设计新人流量扶持、创作者等级和分发规则的灰度实验 | 扶持预算、名称与规则、实验上线和扩量条件 |

四个问题形成“识别流失—判断流量—打通变现—验证策略”的闭环。不能只回答“哪类创作者表现好”，还要说明“平台改变什么规则后，哪类创作者会新增多少有效行为，以及会造成什么连带影响”。

## 二、分析范围、时间窗口与核心口径

### 2.1 分析范围

- 产品范围：图文内容社区主站，包含自然推荐、关注页、活动页带来的内容消费；不包含直播、站外投放落地页和平台官方账号内容。
- 用户范围：中国大陆地区真实注册账号；排除测试账号、内部账号、机器人和封禁后产生的异常行为。
- 内容范围：创作者发布的图文笔记，包括单图、多图、长图文；只将公开可分发且审核通过的笔记计入主分析。
- 经营范围：笔记广告分成、挂商品链接产生的佣金；不把平台广告主投放预算直接当作创作者收益。
- 分析粒度：创作者维度用于留存、分层和策略；笔记维度用于流量效率和变现归因。两张表通过 `creator_id` 关联。
- 地域与时间：统一按北京时间（Asia/Shanghai）切日，所有日期区间均包含起止日。

### 2.2 时间窗口

| 窗口 | 日期 | 用途 |
|---|---|---|
| 历史特征窗口 | 2025-09-01 至 2026-01-31 | 构建创作者行为和内容表现特征 |
| 流失标签窗口 | 2026-02-01 至 2026-02-28 | 判断创作者是否发生 28 天停更流失 |
| 数据快照日 | 2026-02-28 | 创作者属性、粉丝数和状态快照 |
| 数据提取日 | 2026-03-31 | 给 2 月产生的订单和退款留足结算成熟期 |
| 笔记流量观察窗 | 发布日起连续 7 个自然日 | 曝光、点击、阅读和互动 |
| 笔记成交观察窗 | 发布日起连续 30 个自然日 | 商品点击、订单、退款、GMV 和佣金 |

新创作者以首次公开笔记发布时间作为第 0 天。D30 留存观察其第 8 至第 30 天是否再次发布有效笔记。2026 年 2 月才首次发布的创作者只用于新人漏斗和早期行为分析，不进入已成熟的 D30 留存或 28 日流失模型。

### 2.3 创作者相关口径

| 指标 | 正式定义 | 关键排除项 |
|---|---|---|
| 有效创作者 | 分析期内至少发布 1 篇有效公开图文笔记的账号 | 仅注册、只保存草稿、只评论或点赞的普通用户不计为创作者 |
| 新人创作者 | 首次有效公开笔记发布于分析期内的创作者；以历史首发时间识别，不能只看注册时间 | 曾发布后删除的历史创作者不重复算新人；迁移账号按自然人映射 |
| 发布活跃创作者 | 指定统计窗内至少发布 1 篇有效公开笔记的创作者，按 `creator_id` 去重 | 登录、浏览、草稿编辑不算发布活跃 |
| 28 日活跃创作者 | 在统计日向前 28 个自然日内至少发布 1 篇有效公开笔记 | 停用、封禁、注销前行为按有效性规则剔除 |
| 留存 D30 | 首次有效发布后的第 8 至第 30 天内，至少再次发布 1 篇有效公开笔记 | 首篇发布当天不计入再次发布；定时发布按实际公开时间 |
| 主流失定义 | 1 月发布活跃且账号年龄不少于 30 天的创作者，在 2 月连续 28 天没有发布有效公开笔记 | 不把卸载、未登录或只浏览等同于流失；状态不是“卸载”数据 |
| 流失日 | 连续无发布窗口的第 1 天，而不是发现流失的日期 | 注销、永久封禁单独标记为结构性退出，不进入常规流失模型 |
| 变现创作者 | 在指定结算窗内获得大于 0 元的已结算广告分成或带货佣金 | 仅有点击、下单、预估收入但未结算不算已变现 |
| 首次变现 | 创作者历史上首次获得大于 0 元的已结算创作者收益 | 退款冲回导致月净收益为 0 时，不认定为该月成功变现 |

**口径说明：** “流失”在本项目中是运营可干预的“停更状态”，不是用户卸载。若业务需要同时观察卸载，应另建设备与账号退出事件口径，不能混在同一个标签里。

### 2.4 笔记流量与互动口径

| 指标 | 正式定义 | 去重与归因规则 |
|---|---|---|
| 有效曝光 PV | 笔记卡片进入用户可视区域且可见面积不低于 50%、停留至少 1 秒的展示次数 | 同一用户同一天多次曝光可计多次 PV；机器人、后台预览、自己查看自己的笔记剔除 |
| 有效曝光 UV | 观察窗内对笔记产生至少 1 次有效曝光的去重用户数 | 按 `user_id × note_id × 自然日` 去重；设备 ID 只用于补全，不能替代账号 ID |
| 有效点击 PV | 点击笔记卡片、封面或标题进入详情页的次数 | 返回后重复点击可计 PV；误触过滤、作者本人点击、异常高频点击剔除 |
| 有效点击 UV | 观察窗内对笔记产生至少 1 次有效点击的去重用户数 | 按 `user_id × note_id × 自然日` 去重；点击 UV 不得大于曝光 UV |
| CTR | 7 日点击 UV ÷ 7 日曝光 UV | 分子分母使用同一笔记、同一 7 日窗口和同一有效性规则 |
| 阅读时长 | 进入详情页后处于有效阅读状态的平均秒数 | 超长挂机、切后台和异常脚本访问剔除 |
| 完读率 | 阅读进度达到 80% 的阅读 UV ÷ 有效阅读 UV | 分母是进入详情并有有效阅读行为的用户 |
| 互动量 | 点赞数 + 评论数 + 收藏数 + 分享数 | 四个动作分别保留；同一用户可贡献多类互动，不能直接把“互动量”当互动人数 |
| 有效互动量 | 在互动量基础上剔除作者自互动、重复灌水、辱骂被折叠内容和异常账号互动 | 评论删除后按内容治理策略冲回；数据字典保留原始结果标识 |
| 互动率 | 有效互动量 ÷ 有效点击 UV | 作为点击后的互动效率；互动量可能大于点击 UV，因此结果允许大于 100% |
| 互动渗透率 | 发生至少 1 次有效互动的去重用户数 ÷ 有效点击 UV | 更接近“有多少点击用户参与互动”，用于补充互动量口径 |
| 关注转化数 | 因浏览该笔记而新关注作者的去重用户数 | 采用笔记后链路归因，排除作者原有粉丝和互相关注 |
| 负反馈率 | 负反馈次数 ÷ 有效曝光 PV × 1000 | 负反馈包括不感兴趣、减少推荐、举报等，按每千次曝光展示 |
| 商品点击 UV | 从该笔记商品挂载进入商品详情页的去重用户数 | 30 日最后有效触点归因；站外或自然搜索进入商品页不计入该笔记 |
| 付费买家 UV | 在点击商品后完成支付且订单未取消的去重买家数 | 30 日最后有效笔记触点归因，同一订单只归一篇笔记，退款单独冲减 |
| 商品点击率 | 商品点击 UV ÷ 有效点击 UV | 仅对带有效商品链接的笔记计算 |
| 购买转化率 | 付费买家 UV ÷ 商品点击 UV | 分母不为 0 时才计算；用买家 UV 而不是订单数，避免多单用户的规模偏置 |
| 净 GMV | 成交 GMV − 退款 GMV | 退款以订单支付日归属笔记，不能把退款放到退款发生日 |
| 广告 RPM | 30 日结算广告分成 ÷ 7 日有效曝光 UV × 1000 | 说明“每千个曝光 UV 对应多少创作者广告收益” |
| 佣金收入 | 净 GMV × 有效佣金率，再扣除平台调整项 | 佣金率按结算时点的类目规则，不能用当前版本倒算历史 |
| 创作者总收益 | 已结算广告分成 + 已结算带货佣金 | 不包含粉丝打赏、平台补贴、活动奖励和提现 |

**跨周期指标必须成对出现：** `exposure_uv_7d` 与 `click_uv_7d` 可以组成 CTR；不能拿 7 日曝光和 30 日成交计算“成交率”并称其为内容转化率，除非明确标为“30 日成交/7 日曝光”的混合分母指标。

## 三、数据模型、数据字典与模拟数据集

### 3.1 表关系

```text
创作者基础信息表（20,000 行，1 个 creator_id 1 行）
                1
                │
                │ creator_id
                ▼
笔记内容行为表（100,000 行，1 个 note_id 1 行，1 个 creator_id 可对应多篇笔记）
```

两表合计 120,000 行。创作者表用于留存、分层和策略归因；笔记表用于流量、互动、成交和收益拆解。`period_*` 字段只汇总 2025-09-01 至 2026-01-31 的特征窗，`churn_28d` 是 2 月观测得到的标签；建模时禁止把标签窗口行为引入特征。

### 3.2 创作者基础信息表 `creator_profile`

主键：`creator_id`。一行代表一个创作者在快照日的画像、历史行为和流失标签。

| 字段 | 类型 | 含义与取值 | 约束 / 说明 |
|---|---|---|---|
| creator_id | VARCHAR(16) | 创作者唯一标识，如 C000001 | 主键 |
| user_id | VARCHAR(16) | 平台账号标识，如 U100001 | 用于关联用户行为；对外脱敏 |
| account_created_at | DATETIME | 账号注册时间 | 北京时间 |
| creator_activated_at | DATETIME | 注册为创作者的时间 | 注册创作者不等于发布活跃 |
| first_publish_at | DATETIME | 历史首次有效公开笔记发布时间 | 用于新人判定和 D30 观察 |
| last_publish_at | DATETIME | 截至数据提取日最后一次有效公开发布时间 | 可为空；提取日允许晚于画像快照日 |
| snapshot_date | DATE | 画像快照日 | 统一为 2026-02-28 |
| feature_cutoff_date | DATE | 特征截止日 | 统一为 2026-01-31 |
| cohort_month | VARCHAR(7) | 新人首月或存量创作者的观察月份，如 2025-10 | 新人按首发月，存量按 2025-09 |
| creator_stage | VARCHAR(16) | 新人、成长期、稳定期、成熟期、回流期 | 由生命周期规则派生，保留规则版本 |
| is_new_creator | TINYINT | 1=分析期内首次发布的新人，0=存量创作者 | 以历史是否发布为准，不只看注册 |
| acquisition_channel | VARCHAR(32) | 自然注册、站内活动、KOC 邀请、外部投放、老带新等 | 用于渠道质量与选择偏差分析 |
| device_os | VARCHAR(16) | iOS、Android、HarmonyOS、Other | 设备快照，不做自然人口属性推断 |
| city_tier | VARCHAR(16) | 一线、新一线、二线、三线及以下、未知 | 统一城市分级映射 |
| primary_category | VARCHAR(32) | 美食、旅行、穿搭、美妆、家居、母婴、数码、其他 | 创作者一级内容类目 |
| creator_level | TINYINT | 创作者等级 0 至 7 | 取快照等级；等级规则迭代需记录版本 |
| verification_type | VARCHAR(16) | 未认证、个人认证、专业认证、机构认证 | 用于控制身份带来的流量差异 |
| support_group | VARCHAR(24) | 对照组、流量扶持、培训扶持、组合扶持 | 新人策略分组；存量创作者为无扶持 |
| assignment_method | VARCHAR(20) | 随机实验、规则定向、自主报名 | 做因果归因时必须区分，不能混估增量 |
| baseline_fan_cnt | INT | 首次发布或特征窗开始时的粉丝数 | 避免用期末粉丝数解释历史表现 |
| first_7d_publish_cnt | INT | 新人首次发布后 7 个自然日内的有效发布篇数 | 存量创作者为空；新人最少为 1 |
| first_7d_exposure_uv | BIGINT | 新人首篇发布后 7 日累计曝光 UV | 存量创作者为空；可含多篇笔记，按用户去重 |
| first_7d_click_uv | BIGINT | 新人首篇发布后 7 日累计点击 UV | 存量创作者为空；不得超过同口径曝光 UV |
| first_7d_interaction_cnt | BIGINT | 新人首篇发布后 7 日有效互动量 | 存量创作者为空；作者自互动剔除 |
| period_publish_cnt | INT | 特征窗内有效公开发布篇数 | 2025-09-01 至 2026-01-31 |
| period_active_days | INT | 特征窗内至少发布 1 篇有效笔记的自然日数 | 按北京时间去重 |
| period_exposure_uv | BIGINT | 特征窗内笔记曝光 UV 合计 | 跨笔记不可直接去重用户，作为笔记贡献合计使用 |
| period_click_uv | BIGINT | 特征窗内笔记点击 UV 合计 | 与曝光保持相同笔记集合 |
| period_interaction_cnt | BIGINT | 特征窗内有效互动量合计 | 不含自己账号互动 |
| period_ad_revenue | DECIMAL(12,2) | 特征窗内笔记的已结算广告分成，单位元 | 退款和结算冲回已处理 |
| period_commission_revenue | DECIMAL(12,2) | 特征窗内笔记的已结算带货佣金，单位元 | 不等于 GMV |
| first_monetization_at | DATETIME | 首次产生正收益的笔记发布时间代理值 | 项目模拟口径；生产环境优先使用结算时间 |
| monetization_status | VARCHAR(16) | 未变现、仅广告、仅佣金、双渠道 | 按结算结果而非预估收入 |
| churn_label_eligible | TINYINT | 1=进入 2 月流失标签评估，0=样本未成熟或不满足活跃条件 | 防止新人观察期不足造成假流失 |
| churn_28d | TINYINT | 1=2 月连续 28 天未发布有效笔记，0=未流失，空=不适用 | 主流失标签；禁止作为特征 |
| churn_date | DATE | 流失观察窗内首个无发布判断日 | 空值表示未流失或不适用 |
| account_status | VARCHAR(16) | 正常、禁言、封禁、注销、测试 | 封禁与注销单独处理 |
| data_version | VARCHAR(16) | 数据版本，如 sim_v1.0 | 支持口径与结果复现 |

### 3.3 笔记内容行为表 `note_behavior`

主键：`note_id`；外键：`creator_id`。一行代表一篇笔记及其固定观察窗表现。

| 字段 | 类型 | 含义与取值 | 约束 / 说明 |
|---|---|---|---|
| note_id | VARCHAR(18) | 笔记唯一标识，如 N000001 | 主键 |
| creator_id | VARCHAR(16) | 发布创作者，如 C000001 | 外键，关联创作者表 |
| publish_time | DATETIME | 笔记实际公开时间 | 定时发布按公开时间；北京时间 |
| content_type | VARCHAR(16) | 单图、多图、长图文、清单型 | 图文站内内容形态 |
| content_category | VARCHAR(32) | 笔记一级类目 | 用于类目控制 |
| topic_tag | VARCHAR(32) | 主话题标签，如 城市漫游、通勤穿搭 | 分析内容供给结构 |
| title_length | SMALLINT | 标题字符数 | 统一按 Unicode 字符数 |
| body_length | INT | 正文与图文字符数 | 不含商品标题和外部链接 |
| image_cnt | SMALLINT | 笔记图片数量 | 长图文也可记录封面图数 |
| content_quality_score | DECIMAL(5,2) | 内容质量分 0 至 100 | 模型分，必须保留模型版本和计算时间 |
| has_product_link | TINYINT | 1=挂商品链接，0=未挂 | 用于变现漏斗和自然流量干扰分析 |
| product_category | VARCHAR(32) | 商品一级类目；无挂链为空 | 与内容类目分开 |

| data_version | VARCHAR(16) | 数据版本，如 sim_v1.0 | 与创作者表一致 |

### 3.4 模拟数据集设计

这份模拟数据不是随机噪声，而是先设定可解释的业务结构，再生成符合这些结构的两张表，便于完整跑通留存、流量、变现和策略分析。

- 20,000 个创作者：其中 13,000 个新人、7,000 个存量创作者；每个有效创作者至少有 1 篇笔记。
- 100,000 篇笔记：约 200 个头部创作者、1,700 个成长期创作者、6,100 个中间层创作者、12,000 个长尾创作者；尾部创作者大多只有 1 篇，形成明显的“发几条就停更”现象。
- 新人策略分为对照组、流量扶持、培训扶持和组合扶持；部分为随机实验，部分为定向或自主报名，故意保留选择偏差供分析时识别。
- 首周曝光与内容质量、类目、粉丝基础、扶持组和发布频次相关，并通过后续行为影响留存；模型必须使用首周特征预测后续流失，而不是反过来。
- 头部创作者广告分成贡献更高，长尾创作者即使偶尔出爆款也未必有稳定商品转化；变现分析需要区分广告和佣金，不能把一个“GMV 高”直接翻译成“平台收入高”。
- 2 月存在平台活动影响，1 月与 2 月的发布量差异不能直接解释为产品体验变化；算法 V3.0 在 2026-01-15 上线，需使用同版内容、同质量档位和版本前后对照。

数据集中不包含手机号、真实昵称、真实设备和可识别个人的内容正文。金额使用人民币元，比例字段在未进入指标计算前一律保留原始分子和分母。

## 四、核心指标体系

### 4.1 创作者健康指标

| 指标 | 计算方式 | 业务含义 | 决策使用 |
|---|---|---|---|
| 注册转发布率 | 有效发布新人数 ÷ 新注册人数 | 注册后是否真正开始创作 | 判断注册引导和首篇发布门槛 |
| 首篇完成率 | 完成首篇有效公开的人数 ÷ 进入创作流程人数 | 编辑、审核、发布链路是否顺畅 | 产品漏斗优化 |
| D1 / D7 / D30 留存 | 指定观察窗内再次有效发布的人数 ÷ 达到观察期的新人数 | 新人是否形成二次发布和持续创作 | 运营触达与新人任务 |
| 28 日流失率 | `churn_28d=1` 的有效样本 ÷ 可评估样本 | 停更规模和趋势 | 分层预警、召回优先级 |
| 二次发布率 | 首篇后 7 日内发布第 2 篇的人数 ÷ 首篇有效发布人数 | 新人从尝鲜到习惯的关键行为 | 新人扶持的核心过程指标 |
| 月均发布篇数 | 有效发布篇数 ÷ 月活跃创作者数 | 内容供给强度和稳定性 | 创作者健康与供给侧 |
| 活跃天数 | 统计窗内至少发布 1 篇有效笔记的去重自然日数 | 发布是否持续而非集中冲量 | 识别刷任务和短期活动用户 |
| 首周出圈率 | 首周曝光 UV 达到同批次 P80 的新人数 ÷ 新人数 | 是否有早期爆款机会 | 判断流量冷启动门槛 |
| 内容质量提升率 | 最近 3 篇质量分中位数 − 首 3 篇质量分中位数 | 扶持是否带来内容能力提升 | 区分纯补贴和真实成长 |
| 成长跃迁率 | 观察期末等级或流量分层高于期初的人数 ÷ 基线人数 | 创作者能否从低阶走向中高阶 | 创作者等级和流量阶梯设计 |
| 头部集中度 | 前 1% / 前 10% 创作者的曝光或收益占比 | 流量与收益是否过度集中 | 评估生态健康和规则公平 |
| 创作者收益基尼系数 | 按创作者收益排序计算 | 变现收益分配不均程度 | 研究长尾变现和收益拐点 |
| 停更前预警覆盖率 | 被预警且 28 日内流失的人数 ÷ 全部流失人数 | 预警模型是否抓到重点人群 | 运营名单时效和模型覆盖率 |

健康指标不只看“留存高不高”，还要看“留下的创作者是否持续供给、质量是否提升、是否没有牺牲用户体验”。否则活动激励可能制造大量低质量任务内容。

### 4.2 内容流量指标

| 指标 | 计算方式 | 业务含义 | 需要注意 |
|---|---|---|---|
| 有效曝光 UV / PV | 去重用户数 / 展示次数 | 内容是否被看见 | 推荐卡曝光和详情页阅读分开 |
| CTR | 点击 UV ÷ 曝光 UV | 封面、标题和首屏卡片的吸引力 | 分母必须同笔记、同 7 日窗 |
| 阅读时长 | 有效阅读用户的平均秒数 | 内容是否被真实消费 | 只算进入详情后的有效阅读 |
| 完读率 | 完读 UV ÷ 有效阅读 UV | 内容结构与长度是否匹配 | 需按内容形态分层 |
| 互动率 | 有效互动量 ÷ 点击 UV | 点击后是否产生深度参与 | 量口径，不冒充互动人数 |
| 互动渗透率 | 有互动的去重人数 ÷ 点击 UV | 参与广度 | 与互动率同时报告 |
| 关注转化率 | 新增关注 UV ÷ 点击 UV | 内容是否带来粉丝资产 | 排除原有粉丝和互关 |
| 负反馈率 | 负反馈次数 ÷ 曝光 PV × 1000 | 内容是否伤害体验 | 作为流量策略护栏 |
| 人均曝光 | 曝光 UV ÷ 有效笔记数 | 单篇内容平均分发规模 | 对长尾分布使用中位数和P90补充均值 |
| 流量效率 | 点击 PV ÷ 曝光 PV 或有效阅读 UV ÷ 曝光 UV | 分发是否把内容送到匹配用户 | 不能只看曝光规模 |
| 内容供给量 | 有效公开笔记数 | 平台内容池规模 | 需同时检查重复、低质和审核拒绝 |
| 内容质量曝光占比 | 高质量笔记曝光 UV ÷ 总曝光 UV | 分发是否奖励质量 | 质量分阈值需要版本化 |
| 新老创作者流量占比 | 新人 / 存量曝光 UV ÷ 总曝光 UV | 新老结构是否健康 | 结合 CTR、负反馈和留存看 |
| 流量集中度 | 前 1% / 前 10% 笔记或创作者曝光占比 | 是否被少数内容吸收 | 不能单独判断好或坏 |
| 算法版本差异 | 同质量档位在 V2.1、V3.0 的曝光和互动差异 | 迭代是否改变流量结构 | 用自然实验或断点分析 |

### 4.3 变现收益指标

| 指标 | 计算方式 | 业务含义 | 决策使用 |
|---|---|---|---|
| 变现创作者率 | 已变现创作者数 ÷ 活跃创作者数 | 多少活跃创作者获得收益 | 商业化渗透率 |
| 人均月收益 ARPPC | 已结算总收益 ÷ 活跃创作者数 | 平台创作者平均收益 | 需同时看中位数 |
| 变现者人均收益 ARPPU | 已结算总收益 ÷ 已变现创作者数 | 已变现者的经营规模 | 区分覆盖与深度 |
| 首次变现阶段转化率 | 首篇后 30/60 日首次变现人数 ÷ 新人数 | 新人能否获得第一次正反馈 | 设计首单任务 |
| 广告 RPM | 广告分成 ÷ 曝光 UV × 1000 | 每千次曝光的广告变现效率 | 不能与到店成交混算 |
| 商品点击率 | 商品点击 UV ÷ 点击 UV | 内容到商品的意向强度 | 选品和挂链产品 |
| 购买转化率 | 付费买家 UV ÷ 商品点击 UV | 商品页和价格是否承接需求 | 商业化漏斗 |
| 每千曝光 GMV | GMV ÷ 曝光 UV × 1000 | 内容流量到交易规模 | 与佣金率联合看 |
| 净 GMV | 成交 GMV − 退款 GMV | 扣除退货后的交易规模 | 避免把退款当收入 |
| 佣金率 | 佣金收入 ÷ 净 GMV | 平台分成政策和类目差异 | 政策分析 |
| 单位扶持收益 | 策略新增收入 ÷ 策略成本 | 扶持是否产生可持续收益 | 与留存、用户体验共同评估 |
| 收益集中度 | 前 1% / 前 10% 创作者收益占比 | 收益是否被头部吸收 | 长尾生态评估 |
| 双渠道变现率 | 同时有广告和佣金收益的人数 ÷ 已变现人数 | 收益结构是否多元 | 产品组合和创作者教育 |

指标解释要区分“规模、效率、结构、质量”。例如 GMV 是规模，购买转化率是效率，头部收益占比是结构，负反馈率是质量护栏。只报规模容易把平台活动或头部单点爆发误当成整体改善。

## 五、分析整体思路链路

### 5.1 数据采集

1. 从账号与创作者系统获取注册、创作者的激活、等级、认证、扶持分组和账号状态。
2. 从内容系统获取笔记发布时间、类目、图片数、质量分、商品挂载、活动 ID、算法版本和审核状态。
3. 从埋点日志获取曝光、点击、阅读、互动、关注和负反馈，按 `user_id × note_id × date` 形成日粒度事件。
4. 从商品和订单系统获取商品点击、订单、支付、退款、GMV 和结算状态。
5. 从实验与运营系统获取扶持分组、分配方式、活动规则和执行日期，保留实验与定向名单，便于区分因果增量与目标用户自然表现。

### 5.2 数据清洗

- 对账号、创作者、笔记、订单做唯一键校验，处理账号合并、设备换绑、作者注销后主键失效。
- 对曝光、点击、互动和订单按用户、笔记、日期、订单号去重；统一去重发生在指标计算之前。
- 剔除测试账号、内部账号、机器人、异常高频访问、作者自点击和自互动、无效商品链接和取消订单。
- 把定时发布统一到实际公开时间；把跨零点的会话统一到自然日；把退款归回原订单所属笔记。
- 检查不变量：点击 UV ≤ 曝光 UV；付费买家 UV ≤ 商品点击 UV；退款 GMV ≤ 成交 GMV；互动量等于四类互动加总。
- 保留原始值、清洗原因和 `data_version`，不覆盖原始导出；所有排除项都进入口径说明。

### 5.3 探索性分析

- 先看数据完整性、日期覆盖、缺失率、重复率、极端值和创作者量级分布的偏态。
- 用分位数和中位数而不是只看均值描述曝光、GMV 和收益，单独展示 P90、P95、P99 和头部集中度。
- 按新人/存量、首月、内容类目、创作者等级、扶持组、算法版本做同期对比。
- 画创作者生命周期漏斗、留存曲线、曝光—点击—互动—成交漏斗、洛伦兹曲线和按类目的收益贡献。
- 先做单变量与时间趋势，再做多变量模型；任何“某类创作者变现高”的结论都要检查内容质量、粉丝基础、类目和活动影响。

### 5.4 分层

创作者分层不只看粉丝数，建议同时用“内容供给 × 流量效率 × 变现能力”三个维度：

- 生命周期层：首篇未完成、D1/D7 尝鲜、D8–D30 成长期、稳定发布、成熟经营、回流和结构性退出。
- 行为层：单篇停更、低频稳定、高频稳定、爆款偶然型、商业挂载型。
- 价值层：UV 与 CTR 高但未变现、流量一般但商品转化高、变现高但负反馈高、粉丝多但内容供给下降。
- 机会层：高流失风险 × 高扶持敏感度 × 可控成本，形成运营优先队列；不能只按历史 GMV 排序。

分层规则必须版本化。面试中要能说明阈值来自业务目标或分位数，而不是为了把人群凑成漂亮的四象限。

### 5.5 归因

1. **流失归因：** 先用生存曲线比较不同批次，再用 Cox 或逻辑回归控制首周曝光、发布频次、质量、类目、粉丝基础、渠道和活动；报告相关系数、置信区间和校准效果，不把预测重要性直接称为因果。
2. **流量归因：** 用同质量档位、同内容类目、同算法版本比较新人/存量的曝光与 CTR；加入创作者固定效应和时间固定效应；观察算法上线前后的断点，而不是比较两个完全不同月份。
3. **扶持增量：** 对随机实验组比较留存、二次发布、内容供给、广告 RPM、佣金和负反馈；对定向扶持使用倾向得分匹配或双重差分，并说明仍需满足的共同趋势假设。
4. **变现归因：** 按 `曝光 × CTR × 商品点击率 × 购买转化率 × 客单价 × 佣金率` 拆解贡献，分别计算广告和佣金，识别是流量不足、需求不匹配还是结算效率问题。
5. **策略组合：** 用“增量有效创作者数、增量内容供给、增量净收益、单位成本、用户体验护栏”评估策略，不只用一个留存率或 GMV 数字。

### 5.6 策略输出

- **对新人：** 首篇发布后 24 小时触达，提供“第二篇选题模板、内容诊断、首周流量券”；把流量扶持与内容质量门槛绑定，避免只补贴发布次数。
- **对高潜低流量内容：** 优先校验质量分、类目供需和首屏 CTR；在不增加负反馈的前提下增加小流量试探，达到质量阈值的再扩量。
- **对可变现创作者：** 用广告与佣金分层配置；对商品点击高但成交低的人优先改善选品和商品页，对流量高但转化低的人优先改善内容承接。
- **对产品：** 上线新人池、二次发布任务、内容质量分反馈和算法版本灰度；核心指标不是“多给曝光”，而是“新增有效创作者、二次发布、后链路变现和用户体验同时改善”。
- **对组织：** 产出周度创作者健康看板、月度分层名单、实验复盘的同一套口径；把流失预警、扶持实验和收益看板放在同一数据版本上。

## 六、风险、混淆变量与应对方案

| 风险 / 混淆因素 | 可能造成的错误结论 | 应对方式 |
|---|---|---|
| 用注册时间判断新人 | 把长期潜水后首次发笔记的人漏算或重复算入 | 以历史首次有效公开笔记时间为准，保留历史删除和迁移校验 |
| 用卸载替代停更 | 把“卸载但仍有粉丝流量收益”和“未卸载但无发布”混为一谈 | 停更、卸载、封禁、注销分别建标签，主流失只讲停更 |
| 观察期不足 | 新人在月末发布被误判为流失 | 设置成熟期门槛和右删失；标签只取可评估样本 |
| 曝光反向因果 | 互动高导致更多曝光，却被解释为互动带来留存 | 使用首周固定窗口、创作者/时间固定效应和实验验证 |
| 内容质量与流量互为因果 | 高流量笔记被质量分模型打高分，形成循环 | 固定质量分版本和计算时点，使用发布前或模型盲评分数 |
| 头部极值拉动均值 | 少数爆款让整体平均 GMV 看起来很高 | 同时报告中位数、分位数、贡献占比和分层结果 |
| 平台活动与季节性 | 春节、双十一、平台任务导致发布量或成交异常 | 加入活动 ID、月份和节假日控制；比较同批次、同活动强度 |
| 算法版本迭代 | 版本变化和内容质量变化混在一起 | 保留算法版本、同质量配平、断点回归和灰度实验 |
| 扶持选择偏差 | 运营优先挑高潜创作者，导致扶持效果被高估 | 随机实验优先；定向组用匹配/双重差分并做敏感性分析 |
| 商品挂载影响自然流量 | 商业内容曝光低，不一定说明内容质量差 | 分开估计自然曝光与商业转化，控制 `has_product_link` 和商业标识 |
| 退款与结算滞后 | 成交当月高估收益，退款下月才出现 | 设置 30 天成熟期和结算状态；收益统一用已结算口径 |
| 跨设备与账号合并 | 曝光、点击、买家 UV 重复或错配 | 建立账号主键映射；设备 ID 只辅助补全 |
| 受污染实验组 | 运营在实验外额外触达，导致增量无法归因 | 保留曝光剂量、触达时间和剔除规则；按意向治疗和实际治疗分别看 |
| 幸存者偏差 | 只看留下来的创作者，低估早期停更问题 | 保留所有可评估新人，分析分母固定，不能倒推存活样本 |
| 指标游戏 | 只追求发布篇数或 GMV，产生低质内容和刷单 | 设置质量、负反馈、退货率和有效买家为护栏 |
| 多重比较 | 同时测试大量分层，偶然找到显著差异 | 预先定义主次指标，控制检验数量，报告置信区间 |
| 数据穿越 | 用 2 月行为预测 2 月流失，或循环使用变现标签 | 固定特征截止时点，训练/验证按时间切分 |

**结论表达规则：** “高相关”写成高相关，“经实验/准实验支持的增量”才写成因果。策略上线前至少验证一个主指标和三个护栏指标：创作者留存、二次发布、内容质量、负反馈和净收益。

## 七、面试展示时建议的结论结构

项目最终不应只展示一堆指标，而应按以下顺序讲清业务闭环：

1. **先定义问题：** 新人停更不是单一运营问题，而是首周信心、流量反馈、内容能力和变现路径共同作用的结果。
2. **再说明口径：** 停更、活跃、变现和曝光分别如何定义，为什么不能混用；发现日和流失日有什么区别。
3. **再展示证据：** 用留存曲线、流量集中度、漏斗和分层结果回答问题，而不是直接抛模型。
4. **最后给策略：** 用实验结果或准实验说明增量，给出扶持对象、触达时点、预算优先级和护栏指标。

在简历中可写成：“搭建 12 万行创作者—笔记双层分析数据模型，统一定义新人留存、28 日停更、曝光点击互动和广告/佣金结算口径；通过分层、漏斗、生存分析和扶持实验识别新人流失关键节点，输出新人流量池与首周二次发布策略，并用留存、内容质量、负反馈和净收益做策略评估。”

上述简历表述只描述项目方法和分析职责，不填入未经真实数据验证的提升比例。
