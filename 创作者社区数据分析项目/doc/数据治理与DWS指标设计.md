# 内容社区 APP 创作者成长与变现归因：数据治理与 DWS 指标设计

本环节承接 `creator_profile` 与 `note_behavior` 两张基础表，完成 ODS → DWD → DWS 的治理和指标落地。分析快照日为 **2026-02-28**，历史特征窗为 **2025-09-01 至 2026-01-31**，流失标签窗为 **2026-02-01 至 2026-02-28**，数据提取日为 **2026-03-31**。

## 0. 分层与表约定

| 层级 | 表 | 主要职责 | 是否改变原始数据 |
|---|---|---|---|
| ODS | `ods_creator_profile`、`ods_note_behavior` | 原始快照、字段和分区按源系统保留 | 否 |
| DWD | `dwd_creator_profile_df`、`dwd_note_behavior_df` | 去重、标准化、过滤标记、质量分级、口径字段固化 | 否，仅新增派生标记 |
| DWS | 创作者生命周期、分层、笔记指标、赛道指标、新人留存指标 | 支持离线分析、分层和归因 | 否 |

`dt` 和 `etl_time` 是技术分区与装载字段，不属于业务数据字典；不写入用户画像或业务口径。所有 ODS 原始记录保留，DWD 对每行同时输出 `is_core_eligible`、`exclude_reason`、`soft_anomaly_reason` 和 `quality_level`，不通过物理删除掩盖问题。

账号治理使用控制维表 `dim_account_risk_df` 承接测试号、内部运营号和人工确认的作弊账号。该表是安全与质量治理的控制维表，不是第三张分析事实表；若生产账号系统已提供等价字段，可在 DWD 中替换为该字段。

## 一、数据清洗与质量管控方案

### 1.1 无效数据识别与处理

| 数据问题 | 识别规则 | 处理方式 | 业务理由 |
|---|---|---|---|
| 空主键 | `note_id`、`creator_id` 或 `user_id` 为空 | 过滤出核心分析；DWD 保留并标记 `S01_NULL_KEY` | 无法关联事实与画像，参与汇总会制造孤儿记录 |
| 测试账号 | `account_status='测试'` 或治理维表 `risk_type='test'` | 过滤出核心分析，标记 `S02_TEST_ACCOUNT` | 测试流量不代表真实供需，且会污染留存和转化率 |
| 内部运营号 | 治理维表 `risk_type='internal'` | 过滤出核心分析，标记 `S03_INTERNAL_ACCOUNT` | 运营任务、人工推流和内部测试会改变自然流量结构 |
| 刷量作弊账号 | 治理维表人工/风控结果为 `cheat_confirmed`；或创作者级异常笔记数 ≥2 且异常笔记占比 ≥20%；或异常笔记数 ≥5 | 过滤出核心分析，标记 `S04_CONFIRMED_OR_SUSPECTED_CHEAT` | 单篇异常可能是爆款或数据抖动，账号级重复异常才构成更强的作弊证据 |
| 笔记未公开发布 | `note_status <> '公开'`，包括撤回、取消、私密、审核拒绝和删除 | 过滤出核心分析，标记 `S05_NOTE_NOT_PUBLIC` | 无法获得公开推荐和自然消费，不属于公开内容供给 |
| 重复上报埋点 | 同一 `note_id` 多次进入 ODS | DWD 优先取 7/30 日窗口已成熟的最新快照，再按 `dt DESC, data_version DESC` 去重；其他版本保留在 ODS 供追溯 | 直接相加会把曝光、点击和收益重复放大；只选最新版可能误取未成熟快照 |
| 发布时间缺失或非法 | `publish_time IS NULL`、无法转换或晚于数据提取日 | 过滤出核心分析，标记 `S06_INVALID_PUBLISH_TIME` | 无法确定 7 日/30 日窗口，也无法判断新人身份 |
| 曝光=0 但收益明显为正 | `exposure_uv_7d=0` 且广告分成 >￥10 或佣金 >￥50 | 过滤并标记 `S07_ZERO_EXPOSURE_REVENUE` | 收益链路必须有曝光触点；较大金额已超过舍入误差和延迟回传可解释范围 |
| 点击大于曝光 | `click_uv_7d > exposure_uv_7d` 或 `click_pv_7d > exposure_pv_7d` | 过滤并标记 `S08_FUNNEL_LOGIC_ERROR` | 点击是曝光的后置事件，逻辑不成立说明埋点或关联错误 |
| 商品成交链路断裂 | 有成交或佣金但无商品链接；付费买家 > 商品点击 UV；退款 > 成交 GMV | 过滤并标记 `S09_COMMERCE_LOGIC_ERROR` | 无商品入口不应产生归因订单，成交和退款必须满足链路约束 |
| 互动加总不一致 | `interaction_cnt_7d` 与点赞、评论、收藏、分享之和不等 | 过滤并标记 `S10_INTERACTION_RECON_ERROR` | 互动总量是互动率的核心分子，不能带着对账差异进入指标 |
| 互动量远高于上限 | `interaction_cnt_7d > 12 × click_uv_7d` 且 `interaction_cnt_7d ≥ 1000` | 软异常；账号级重复出现时升级为可疑作弊 | 单次点击可产生多类互动，但 12 倍且绝对量超过 1000 已远超正常消费结构；相对倍数与绝对量结合避免误杀 |
| 关注转化异常 | `follow_cnt_7d > 0.2 × click_uv_7d` 且 `follow_cnt_7d ≥ 500` | 软异常，保留用于敏感性分析 | 20% 点击转关注已处于极端尾部，但仍可能是强垂类爆款，不应单条硬过滤 |
| 强负反馈 | `negative_feedback_cnt_7d ÷ exposure_pv_7d > 5%` | 软异常，标记内容质量风险 | 5% 明显高于正常推荐内容体验线，但它是治理信号，不等于埋点错误 |
| 阅读时长异常 | `avg_read_seconds_7d > 3600` | 软异常，保留但不进入阅读效率排名 | 1 小时平均值高度可能包含挂机、切后台或脚本流量 |
| 结构性账号退出 | `account_status IN ('封禁','注销')` | 保留历史贡献，排除出扶持策略和流失分母 | 封禁/注销是平台治理事件，与运营可干预的自然停更不应混算 |

**过滤和聚合严格分离：** 以上规则只在 DWD 生成 `is_core_eligible` 和排除原因；DWS 只读取 `is_core_eligible=1`。DWS 中不再临时写“排除测试号”“过滤未公开笔记”等规则。

**阈值治理：** 互动和关注异常阈值上线前使用过去 180 天同内容类目、同内容形态、同算法版本的 P99.5 进行校准，同时保留 12 次/点击、20% 点击转关注、1000/500 绝对量下限，避免小样本产生假阈值；负反馈 5%、阅读 1 小时、零曝光收益 ￥10/￥50 作为经营可解释的护栏值。阈值每月复算一次，调整必须记录版本并观察留存、转化和误杀率，不能因单次业务波动随意放宽。

### 1.2 缺失值分级处理

| 字段类别 | 缺失场景 | 策略 | 是否过滤 | 指标影响 |
|---|---|---|---|---|
| 标签类：`primary_category`、`content_category` | 为空 | 填为“未分类”，保留 `category_missing_flag=1` | 否 | 可进入总量；不进入赛道横向排名和归因主结论 |
| 标签类：`support_group` | 新人为空 | 标记“未知扶持” | 否 | 可从描述统计中剔除；不进入实验增量估计 |
| 标签类：`support_group` | 存量或非实验用户为空 | 按业务语义填“无扶持” | 否 | 仅影响策略解释，不影响留存事实 |
| 标签类：`creator_level` | 为空 | 标记“未分层” | 否 | 不参与等级驱动的策略结论 |
| 标签类：`product_category` | 无商品链接时为空 | 属于预期缺失，保留空值 | 否 | 不进入商品类目分析 |
| 标签类：`product_category` | 有商品链接但为空 | 标记“商品类目未知” | 否 | 进入总 GMV，排除出类目贡献排名 |
| 时间类：`publish_time` | 缺失、无法解析、晚于提取日 | 过滤出核心分析 | 是 | 无法固定 7/30 日窗口 |
| 时间类：`first_publish_at` | 缺失 | 优先由有效笔记最小发布时间重建；仍为空则过滤出创作者核心分析 | 条件过滤 | 无法判新人、D7/D14 留存与入行周期 |
| 时间类：`last_publish_at` | 缺失 | 由有效笔记最大发布时间重建 | 否 | 不重新推导时静默时长不可用 |
| 时间类：`churn_date` | 未流失或不适用时为空 | 保留空值，不填 0 | 否 | 空值表示不适用，和“流失日为 0”不是同一概念 |
| 数值类：曝光、点击、互动 | 观察窗未成熟 | 保留记录并标记 `metric_window_complete=0` | 否 | 不进入分子、分母和均值 |
| 数值类：曝光、点击、互动 | 窗口已成熟但仍缺失 | 保留 NULL 与质量标记，不以 0 代替 | 否 | 排除出转化率分母；在总量表中单独报告覆盖率 |
| 数值类：`baseline_fan_cnt` | 为空 | 保留缺失标记；描述分析可按内容类目和等级中位数补全；归因模型保留缺失指示变量 | 否 | 不参与需精确控制粉丝基础的因果结论 |
| 数值类：广告/佣金收入 | 待结算或已冲回 | 保留结算状态，不用预估收入代替 | 否 | 变现指标只取 `settlement_status='已结算'` |

**核心原则：** “真实为 0”和“没有回传”必须区分。计数类缺失不能用 0 补齐；只有在 DWS 汇总总额时，才可在完整率达标后使用 `COALESCE(...,0)` 并同时输出 `metric_coverage_rate`。

### 1.3 数据可信度分级

| 等级 | 判定规则 | 使用范围 |
|---|---|---|
| 高 | 主键和核心时间完整率 100%；核心数值完整率 ≥99.5%；硬异常率 <0.1%；无软异常 | 可作为核心指标、实验结论和策略决策依据 |
| 中 | 主键与时间合法；核心数值完整率 95%–99.5%；或有软异常但未达到账号级作弊门槛 | 可用于描述性分析和方向判断；因果结论需做敏感性分析 |
| 低 | 核心数值完整率 <95%；硬异常；账号疑似作弊；结构性退出 | 只用于质量审计和数据补充，不进入 DWS 核心指标 |

99.5% 是数据生产可允许的完成度门槛；95% 以下对转化率和人群占比已经可能产生方向性偏差。阈值写入质量监控并在每次口径升级时重新评估。

### 1.4 数据校验规则与采样核验

| 校验类型 | 规则 | 失败处理 |
|---|---|---|
| 主键唯一 | `creator_id` 在创作者表唯一；`note_id` 在 DWD 去重后唯一 | 阻断写入并输出冲突样本 |
| 外键完整 | 有效笔记的 `creator_id` 必须存在于 DWD 创作者表 | 阻断核心指标发布 |
| 时间合法 | `first_publish_at ≤ last_publish_at ≤ data_extract_date`；`publish_time` 不晚于提取日 | 过滤并进入质量报告 |
| 指标值域 | 计数非负；比例在 0–1；退款≤成交；买家≤商品点击；点击≤曝光 | 硬异常过滤，软异常标记 |
| 行级对账 | 点赞+评论+收藏+分享=互动量；净 GMV=成交 GMV−退款 | 不一致进入异常池，不进入 DWS |
| 层间对账 | DWS 曝光/点击/GMV/收益合计等于 DWD 可分析记录合计 | 阻断发布并回溯 |
| 分区与版本 | 同一 `dt` 只使用一个 `data_version`；口径版本写入表 | 保留双版本结果进行差异审计 |

**采样核验方式：**

1. 每日对 `dwd_note_behavior_df` 按 `note_status`、`quality_level`、`exclude_reason`、`content_category` 分层，用固定哈希种子抽取约 0.1% 记录，避免只抽头部或只抽异常。
2. 对抽取样本检查原始状态、发布时间、曝光链路、互动加总、商品链路、结算状态和排除原因，人工复核结果写入质量工单。
3. 将样本异常率与全量分布交叉核对；若样本与全量差异超过 0.2 个百分点，扩大抽样比例。
4. 每次口径或阈值升级，至少保留一份新旧版本差异表，展示人数、笔记数、曝光、收益和留存率的变化。

## 二、DWS 指标与 SQL 交付

执行脚本：

- `sql/01_ods_to_dwd.sql`：控制维表、DWD 去重、过滤、缺失标记和可信度分级。
- `sql/02_dwd_to_dws.sql`：创作者生命周期、分层、笔记、赛道和新人留存 DWS。
- `sql/03_quality_checks.sql`：发布前质量校验、对账和固定种子抽样。

### 2.1 DWS 产出表

| DWS 表 | 粒度 | 主要用途 |
|---|---|---|
| `dws_creator_lifecycle_df` | 快照日 × 创作者 | 首末发文、创作周期、连续活跃、静默、D7/D14 留存、28 日流失和创作者分层 |
| `dws_creator_segment_df` | 快照日 × 创作者层级 | 新人、头部、腰部、尾部规模、内容产量、收益和留存分布 |
| `dws_note_traffic_conversion_df` | 快照日 × 笔记 | 笔记流量、互动、成交、收益和变现效率 |
| `dws_track_performance_df` | 快照日 × 内容赛道 | 各赛道创作者供给、流量分配、留存和变现效率横向比较 |
| `dws_new_creator_retention_detail_df` | 快照日 × 新人 | 首篇笔记表现、分群标签、7/14 天留存标志 |
| `dws_new_creator_retention_df` | 快照日 × 批次 × 首篇分群 | 新人留存分组汇总，直接供归因和运营使用 |

### 2.2 关键派生口径

| 指标 | SQL 口径 | 说明 |
|---|---|---|
| 首篇有效笔记时间 | 有效公开且 `is_core_eligible=1` 的最早 `publish_time` | 不以注册时间代替 |
| 末次有效发文 | 有效公开且可分析笔记的最晚 `publish_time` | 用于静默与生命周期 |
| 创作周期 | `datediff(last_valid_publish_at, first_valid_publish_at)+1` | 首末发文之间的日历跨度，不表示每天连续活跃 |
| 连续创作时长 | 相邻活跃日间隔不超过 7 天的活动段最大跨度 | 7 天与新人留存和第 1 周内容节奏对齐 |
| 静默时长 | `datediff(snapshot_date,last_valid_publish_at)` | 不把未成熟观察窗误算为流失 |
| 入行周期 | `datediff(snapshot_date,first_valid_publish_at)+1` | 以首篇有效公开笔记为起点 |
| 7 天留存 | 首篇后第 1–7 天至少再发 1 篇有效笔记 | 分子是新人，不是笔记；分母是已成熟新人 |
| 14 天留存 | 首篇后第 1–14 天至少再发 1 篇有效笔记 | 与 7 天留存同方向、不同窗口 |
| 28 日流失 | 1 月活跃且账号成熟，2 月连续 28 天无有效公开笔记 | 与 D7/D14“再次发布”不是同一种指标 |
| 创作者层级 | 新人单独标记；存量按特征窗曝光 UV 分层，前 10% 为头部、接下来 40% 为腰部、后 50% 为尾部 | 相对分层避免直接用粉丝数放大存量优势；不用于跨快照日绝对稳定排名 |
| ARPU（本表） | 已结算创作者收益 ÷ 活跃创作者数 | 严格说是每活跃创作者平均收益 ARPPC；不与普通用户 ARPU 混用 |
| 人均笔记产量 | 有效公开笔记数 ÷ 活跃创作者数 | 只用有效公开笔记 |
| 单篇平均变现收益 | 已结算广告分成+佣金 ÷ 有效笔记数 | 不是毛利；没有成本字段 |
| 有效点击率 | 7 日点击 UV ÷ 7 日曝光 UV | 同笔记、同窗口、同去重规则 |
| 正向互动率 | 点赞+评论+收藏+分享 ÷ 点击 UV | 互动量口径，不冒充互动人数 |
| 带货成交转化率 | 付费买家 UV ÷ 商品点击 UV | 不是订单数 ÷ 曝光 |
| 笔记变现效率 | 已结算创作者收益 ÷ 曝光 UV × 1000 | 收入是创作者收益，不是平台毛利 |

## 三、指标口径对齐与敏感性说明

| 指标 | 统计边界 | 排除项 | 统计窗口 | 敏感性 |
|---|---|---|---|---|
| 新人创作者 | 首次有效公开笔记出现在分析期 | 测试号、内部号、确认作弊、无有效发布 | 首篇发布日 | 用注册时间会漏掉潜水后首次发布者；删除历史内容会改变新人识别 |
| 活跃创作者 | 窗内至少发布 1 篇有效公开笔记 | 登录、浏览、草稿、私密和撤回笔记 | 统计窗 | 改成“登录活跃”会显著放大运营用户，不能与发布留存混用 |
| 28 日流失 | 1 月活跃且账号成熟的创作者在 2 月无有效发文 | 封禁、注销、测试、内部、作弊、未成熟 | 2 月 1–28 日 | 改成 14 天会提高流失率；用卸载替代停更会改变业务含义 |
| 7/14 天留存 | 首篇后 1–7 或 1–14 天再次有效发布 | 作者自发布无效、私密、撤回；未达到观察期 | 首篇后累计窗口 | 改成“第 7/14 天当天活跃”会与累计留存产生完全不同的绝对值 |
| 曝光 UV | 同用户同笔记同日去重 | 作者自看、后台预览、机器人、异常流量 | 发布后 7 日 | 改为 PV 会放大重复消费；不按日去重会放大跨天回访 |
| 点击 UV | 同用户同笔记同日详情页点击去重 | 误触、作者自点、异常高频 | 发布后 7 日 | 分母不一致时 CTR 会失去可比性 |
| 互动率 | 四类正向互动量之和 ÷ 点击 UV | 自互动、灌水、折叠或失效评论 | 发布后 7 日 | 改成互动人数 ÷ 曝光会显著降低数值并改变策略排序 |
| 变现转化率 | 付费买家 UV ÷ 商品点击 UV | 未支付、取消、退款订单、无商品链接 | 发布后 30 日 | 改用订单数会受多单用户影响；改用曝光分母会把内容吸引力与商品承接混在一起 |
| 净 GMV | 成交 GMV − 退款 GMV | 取消订单、无效归因订单 | 发布后 30 日 | 退款归回退款日会与内容发布月错位 |
| 创作者收益 | 已结算广告分成 + 已结算佣金 | 预估收益、未结算、活动奖励、提现 | 特征窗/分析窗 | 用 GMV 代替收益会高估平台实际收益 |
| 单笔记毛利 | **当前不可严格计算** | 缺少平台收入分成成本或商品成本 | 不适用 | 用 GMV 或创作者收益冒充毛利会把规模误当利润；补充成本字段后再上线 |
| 创作者层级 | 同快照日相对曝光分位 | 未成熟、无有效笔记、结构性退出 | 特征窗 | 快照日不同或分位阈值变化会让“头部”人员发生变化 |
| 赛道留存 | 新人首篇内容类目归组 | 未分类仅进入总量，不进入赛道排名 | 首篇后 7/14 日 | 类别映射变化会改变赛道样本数 |

**口径变更影响：** 留存窗口、活跃定义、UV/PV、退款归属、结算收入与层级分位点是五类高敏感项。任何一项变更都应同时输出旧口径、DWS 总量变化、规模变化和结论方向变化，不能只替换看板数字。

## 四、指标交付与落地说明

### 4.1 使用对象

- **创作者运营：** 使用 `dws_creator_lifecycle_df` 和 `dws_creator_segment_df` 识别新人停更、D7/D14 低留存、静默和高潜低流量人群。
- **产品/推荐：** 使用 `dws_note_traffic_conversion_df`、`dws_track_performance_df` 观察新老创作者的流量、CTR、互动和负反馈，为新人流量池和算法灰度提供前置分析。
- **商业化：** 使用笔记和赛道变现效率、净 GMV、广告与佣金拆分定位“有流量无成交”或“有成交无结算”。
- **数据科学与实验团队：** 使用 `dws_new_creator_retention_detail_df` 做首篇表现分群、匹配、倾向得分和 AB 实验基线。
- **管理者：** 使用赛道汇总和创作者分层分布判断内容供给、流量集中度和变现规模之间的取舍。

### 4.2 自助查询方式

所有 DWS 表按 `dt` 分区，业务时间统一为北京时间，默认查询最新快照：

| 场景 | 推荐查询 |
|---|---|
| 查看新人首篇表现与 D7/D14 留存 | 按 `cohort_month`、`content_category`、`first_note_segment` 汇总 `dws_new_creator_retention_df` |
| 查找高流失且可控人群 | 在 `dws_creator_lifecycle_df` 过滤 `is_new_creator=1`、`retained_7d=0` 或 `churn_28d=1`，再叠加首篇曝光/互动分群 |
| 查找高流量低收益内容 | 使用 `dws_note_traffic_conversion_df` 的 `note_monetization_efficiency`、`ctr` 和 `commerce_conversion_rate` 做多维筛选 |
| 看赛道机会 | 用 `dws_track_performance_df` 对比 `traffic_share`、`revenue_per_note`、`retention_7d_rate`、`negative_feedback_rate` |
| 做扶持实验前置 | 使用 `dws_new_creator_retention_detail_df` 统计各分群样本、基线留存和基线收入，禁止实验开始后按结果反向加组 |

### 4.3 指标监控方案

- **每日发布前：** 行数同比/环比、主键重复、外键孤儿、时间非法、硬异常率、核心数值完整率、DWD→DWS 对账。
- **每日发布后：** 分层的曝光、CTR、互动率、商品点击率、购买转化率、收入、退款率和留存率变化；比例指标看绝对百分点，不只等比例。
- **质量门槛：** 硬异常率超过 0.1%、核心完整率低于 99.5% 或日环比变化超过 5 个百分点时，先标记“不可用于策略决策”，人工核查后再发布。
- **版本管理：** 每个 DWS 表写入 `metric_version`、`source_version`、`dt`；口径变更建立新旧版本差异表并保留 30 天可回查。
- **抽样复核：** 每周固定抽样 0.1% 记录，复核来源状态、时间、漏斗、互动、商品和结算字段；异常样本回写质量工单。

### 4.4 如何服务扶持与流量 AB 实验

1. **实验前：** 用新人 DWS 按渠道、赛道、首篇曝光分群和首篇互动分群检查样本量与基线 D7/D14 留存，避免把本就有差异的群体混在实验组。
2. **实验设计：** 运营扶持以新人创作者为随机单位，产品流量池以创作者或笔记为随机单位；同一创作者不能被多个扶持策略同时覆盖，避免实验污染。
3. **主指标与护栏：** 新人扶持主指标为 D7/D14 留存、二次发布率和内容供给；产品流量分发主指标为有效曝光、CTR、关注转化；护栏为负反馈率、内容质量、退款率和单篇收益。不能只追求曝光或发布篇数。
4. **实验后：** 用意向治疗（ITT）和实际触达两种口径复算；DWS 只负责提供基线、分层和可评估样本，最终增量仍需实验设计或准实验识别。
5. **上线门槛：** 主指标有稳定正向增量，护栏不出现不可接受的恶化，且新增收益能覆盖扶持成本；否则只保留为局部探索，不直接全量扩量。

## 五、面试口述版

“我先在 ODS 保留原始快照，再把账号治理、笔记状态、去重、时间合法性、漏斗逻辑和异常阈值全部固化到 DWD，并把硬过滤、软异常、缺失和可信度做成显式标记。DWS 不再临时清洗，只消费已认证记录，因此每个指标都能回溯到具体笔记和创作者。留存统一以首篇有效公开笔记为起点，D7/D14 是累计再发文留存，28 日流失是月度停更标签，两者不混用。最后按照创作者、笔记、赛道和新人首篇表现分群产出指标，并在发布前做行数、主外键、漏斗、对账和抽样复核。”
